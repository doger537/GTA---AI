## Что можно проверить сейчас

Запуск `Check-PilotNet-Integration.cmd` выполняет две проверки без управления GTA:

1. Непрерывная аналоговая команда, ограничение скорости изменения стика/газа, просрочка команды, отдельный тормоз и сброс в нейтраль.
2. Двенадцать примеров из существующего набора → настоящая обученная ONNX-модель → адаптер Python → имитатор API vgamepad. Каждый пример содержит четыре различных последовательных кадра. Педали в этой проверке всегда нейтральны. Разница вероятностей правого/левого направления используется как экспериментальная команда стика, а не как измеренный угол руля.

Результаты: `experiments/runs/analog/smoke.json`, `experiments/runs/analog/pilotnet-preview.json`.

## Аналоговый канал

`analog-actuator.mjs` предоставляет `update/start/stop`, как существующий исполнитель клавиатуры. Он передаёт команды `steer` −1..1, `throttle` 0..1, `brake` 0..1 в постоянный процесс `gamepad_backend.py`. Импульсы A/D не используются.

Python отдельно от цикла восприятия обновляет устройство примерно раз в 20 мс. Руль меняется максимум на 1,5 единицы в секунду, газ — на 1 единицу в секунду. Это исходные параметры, не калибровка реакции машины. При торможении газ сразу отпускается; тормоз передаётся отдельным левым курком. Одновременные газ и тормоз отклоняются.

Срок команды — максимум 250 мс. Независимый цикл сбрасывает устройство при просрочке; новая команда не возобновляет истёкший сеанс без явного arm. Реальный режим также проверяет процесс GTA5, фокус окна и F8. Node-адаптер требует мост GTA Control для наблюдения за фокусом, другим исполнителем и изменением поколения остановки — это связывает остановку моста с аналоговым контуром. Потеря связи приводит к истечению команды. Эти механизмы проверены в программной имитации; реакции настоящего устройства и задержки под нагрузкой GTA ещё не измерены.

Реальный backend имеет явный режим `--device=vgamepad` и требует PID GTA. В текущей среде **нет ни пакета vgamepad в окружении проекта, ни обнаруженного системного драйвера ViGEmBus**, поэтому реальный режим не запускался. Обёртка использует [официальный API vgamepad](https://github.com/yannbouteiller/vgamepad/blob/main/README.md). Его обычная Windows-установка запускает установщик системного драйвера; это отдельный шаг настройки компьютера. Поддержка ViGEm завершена — [заявление разработчика](https://docs.nefarius.at/projects/ViGEm/End-of-Life/). Совместимость с текущей GTA Online не проверена.

## Камера с капота

Добавлен `Record-Hood-2-Minutes.cmd`. Он вызывает прежний рекордер со звуковыми сигналами и журналом событий, добавляя `--camera=hood`. Перед стартом нужно вручную включить этот ракурс и сохранять его во время записи. Автоматическое переключение и проверка камеры отсутствуют.

Профиль и статус `user_declared_not_automatically_verified` сохраняются в метаданных. `prepare-dataset.mjs` для hood использует нормализованную область, соответствующую строкам 300–620 при высоте 720. Набор сохраняется с суффиксом `-hood`, отдельно от прежних данных. Старый размер обрезки сохранён точно; разрешение текущих записей не переименовано в 1280×720.

Новых поездок с капота пока нет. Старые поездки не объявлялись такими данными и не использовались как фиктивное обучение этому ракурсу. Для обучения и оценки модели с капота понадобятся отдельные записи с этим видом. Модель и набор с различными объявленными профилями не допускаются к совместной ONNX-проверке.

## PilotNet

Реализован свёрточный каркас PilotNet: 24/36/48/64/64 каналов, ELU, dropout 0,5, плотные слои 100/50/10. Вход — четыре чёрно-белых изображения 66×200. Нормализация выполняется один раз при упаковке в Node, в диапазон −1..1.

В существующих записях есть только клавиатурные метки, поэтому выходы — три прежние категориальные группы управления. Непрерывные углы и «три камеры» из обрезок с выдуманной поправкой не создавались. Это адаптация каркаса, а не точное воспроизведение регрессии измеренного рулевого управления из присланного текста.

Обучение: 832 примера одной поездки, 5 эпох на CPU; проверка: 880 примеров другой поездки. Выбор эпохи по прежнему критерию среднего F1 для A/S/D, затем полному совпадению кнопок. Дневная контрольная поездка не использовалась для обучения или выбора.

**Результат слабый:** выбрана первая эпоха, полное совпадение на проверке 50,57%, ровно как у «всегда W». F1 для A, S и D — 0. Все пять эпох на этой проверке выбирали прямо и газ. На обучение с итоговыми расчётами ушло около 16,3 с. Этот короткий эксперимент не доказывает непригодность архитектуры, но не даёт оснований заменять существующую модель.

Артефакты: `training/trained/pilotnet-integration-v1/` с конфигурацией, всеми эпохами, `best.pt`, `model.onnx` и отчётом. Экспорт проверен настоящим Node ONNX Runtime: максимальное отличие вероятностей от PyTorch около **1,2×10⁻⁷**. Он подключён к прежнему `onnx-controls.mjs`.

## Повторение и ограничения

```text
node analog-smoke.mjs
node pilotnet-analog-preview.mjs
node onnx-controls.mjs trained/pilotnet-integration-v1 --verify
npm test
training-env\Scripts\python.exe -m unittest test_ablation.py test_integration.py
```

Исходник обучения — `train-pilotnet.py`; экспорт входных данных — прежний `export-control-cache.mjs` с профилем `pilotnet-gray-v1`. Образцы сохраняются в реальном порядке времени, без случайного разделения соседних кадров между поездками.

**77 тестов JavaScript и 12 Python прошли.** Проверены размеры и нормализация, сохранность старой обрезки, изменение поколения остановки, просрочка независимо от родительского цикла, потеря фокуса через имитацию, отдельный тормоз и нейтраль. Живой драйвер, реальная плавность движения и вождение нейросетью не проверены. Автопилот в игре автоматически не включается. Основные ограничения восприятия дороги и GPS этим изменением не решены.
