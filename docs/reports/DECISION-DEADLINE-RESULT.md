# Срок решения до Python — 7 ноября 2026

Закрыт разрыв между клиентским DecisionLease и реальным Python-исполнителем: срок решения теперь передаётся вместе с командой и проверяется по исходным часам захвата C#-моста. Задержка в Node.js, stdin или HTTP не даёт команде новые250мс. Работа и проверки выполнены офлайн, без игры, захвата экрана и реального устройства ввода.

## Контракт

Сообщение в Python содержит отдельные `command` и `source`:

```json
{
  "op": "command",
  "command": {"steer": 0.2, "throttle": 0, "brake": 0, "duration_ms": 250},
  "source": {
    "sequence": 1,
    "generation": 7,
    "capture_start_ms": 1000,
    "decision_expires_ms": 1350
  }
}
```

Числа здесь синтетические для объяснения формата. В реальных CLI используются метаданные `/observation`, без придуманных кадров или меток управления.

`decision_expires_ms` фиксируется в DecisionLease при решении: не позднее `capture_start_ms + 450` и оценённого времени решения плюс клиентская аренда. Повтор одного sequence может только сократить срок. Он не обновляется при отправке очередного heartbeat. Значение остаётся в capture-clock моста; UTC, `Date.now()` и часы Python с ним напрямую не сравниваются.

Мост принимает `source` в `/control/check` с длительностью команды. Он проверяет типы/границы чисел, поколение владельца, отсутствие захвата из будущего, истечение срока, порядок sequence и времени захвата. В рамках разрешения владельца фиксируется первый допустимый срок данного кадра. Повтор не может его продлить, новый sequence с тем же/старым временем захвата отклоняется. Просроченное разрешение не оживает от нового кадра: нужен явный arm. Входы без source не продлевают gamepad-аренду.

Ответ `remaining_ms` вычисляется по часам моста с учётом этих ограничений. Python записывает локальное окончание относительно своего монотонного времени **до** сетевого запроса. Издержки запроса вычитаются, после ответа срок проверяется снова. До применения осей проверяются текущий deadline, фокус и разрешение владельца. Повторный source также ограничен первым локальным окончанием. Ошибка/истечение переводит backend в нейтраль, затем освобождается владелец; heartbeat не включает управление заново.

## Изменённые пути

- `DecisionLease.wireSource()` возвращает отдельный снимок метаданных. `AnalogActuator` передаёт его через `GamepadWorker.call('command', command, source)` до Python.
- Реальный `GamepadWorker` отказывает команде без source ещё до записи stdin. Python повторяет проверку независимо от Node.js. Создание `AnalogController` без владельца разрешено только с `MockPad`.
- Калибровка получает HUD/дорогу из единого `/observation`, сохраняет настоящее поколение/время и отправляет source выбранного кадра. Пороги OCR, дозы, длительности и политика калибровки не менялись. Сам CLI не запускали — выполнена проверка синтаксиса и библиотечных контрактов.
- Ограниченные реальные диагностические CLI тоже передают свежий `/observation`. START-pulse требует уже принятую source-команду и достаточный остаток срока. Их реальные испытания не запускались.
- `BridgeOwner` требует feature flag `decision_deadline_supported` до создания реального устройства. Старый мост/старый безвременной протокол не используются как fallback.
- Mock-инструменты могут работать с явно синтетическими источниками. Без настоящего broker они не доказывают соответствие capture-clock; они не создают физическое устройство. Исправлен source в mock smoke; новые отчёты получают отдельные имена, старые не перезаписываются.

Arm сам по себе выполняет нейтраль и проверку владельца, но не создаёт решение для движения. Служебная инициализация драйвера (`initialize_neutral`, включая прежний минимальный шаг стика при необходимости) остаётся отдельной процедурой настройки устройства с проверкой фокуса/F8/владения; это не команда, полученная из кадра, и фиктивный vision-source для неё не создаётся.

Сценарии со временем — явно синтетические. Они проверяют контракт и реакции на отказы, а не динамику машины. Положительный live-путь через настоящее игровое окно не проверялся. Сохранённые кадры, веса и распознавание не менялись; новых измерений FPS/задержки на дороге нет.

Проверенный EXE установлен в `apps/gta-control/GtaControl.exe` и прежний `outputs/GtaControl/GtaControl.exe` при выключенном мосте; хеши совпали. Предыдущие исходники/EXE, тестовые отчёты и manifest сохранены в `work/decision-deadline/`. Обычный режим моста не запускался.

## Что остаётся

Общий `drive-safety-gate`, подтверждённая калибровка/качество наблюдений и проверки в GTA ещё нужны; `trial --drive` остаётся запрещённым. ОС и watchdog не дают жёсткой гарантии физического возврата в нейтраль ровно на границе миллисекунды, особенно при блокирующем I/O/планировании. Нейтраль не гарантирует остановку автомобиля. Этот этап задаёт проверяемый срок решений и отклонение просроченных команд, а не доказывает автономную езду.
