# Общий владелец ввода — 7 ноября 2026

**Актуальный статус:** обязательный source deadline, общий DriveSafetyGate и единый Observation реализованы. См. [SAFETY-CHECKLIST-RESULT.md](SAFETY-CHECKLIST-RESULT.md). Ниже сохранён статус этапа владения; реальные калибровки и автономный проезд ещё не подтверждены.

Реализован механизм исключительного владения вводом для управляемых программой клавиатуры и виртуального геймпада. Проверено офлайн. Игру, обычный режим моста, захват экрана и реальное устройство ввода не запускали.

## Поведение

- C#-мост выдаёт непрозрачное разрешение одному владельцу: `keyboard` или `gamepad`. Команды клавиатуры `/action`, `/step`, `/hold` требуют разрешение своего типа и текущий `generation`; без предварительного arm они отклоняются. Сам запрос команды больше не включает управление.
- `/stop`, F8, потеря фокуса или истечение активного срока отзывают разрешение. Старые команды и heartbeat не восстанавливают его. Новый сеанс требует явного arm с актуальным поколением при фокусе GTA и отпущенном F8.
- При отзыве геймпада C# сохраняет состояние `revoking`. Другой владелец не получает разрешение, пока Python не выполнит `pad.reset()/update()` и не подтвердит освобождение.
- Python проверяет разрешение самостоятельно в watchdog, без участия Node.js. Проверка состояния не продлевает срок; продление происходит при явной arm/команде. Ошибка связи или отзыв ведут к нейтрали и запрету последующих команд до нового arm. Локальные часы повторно проверяются после сетевого запроса, чтобы ожидание HTTP не продлевало старую команду.
- Общая Windows-блокировка `%LOCALAPPDATA%/GTA-AI/input-owner.lock` удерживается C# для клавиатуры и Python для геймпада. `FileShare.None`/`CreateFileW` с share=0 исключают одновременное владение даже через разные процессы моста. Новый мост также не обходит живой Python-backend. Блокировка освобождается после нейтрали; ОС закрывает handle при завершении процесса. Файл не удаляют для принудительного захвата.
- Python захватывает блокировку и резервирует разрешение до создания `VX360Gamepad`. Проверка инициализации нейтрали запрашивает разрешение перед своим минимальным ненулевым шагом стика. Отдельная диагностика `check-gamepad-neutral.py` тоже требует мост и `--pid`.

Это согласование автоматических исполнителей проекта. Оно не блокирует физическую клавиатуру или действия человека в Windows.

## Протокол

| Запрос | Смысл |
|---|---|
| `GET /status` | `ownership_supported`, `input_owner`, `input_state`, `generation`; секрет разрешения не публикуется |
| `POST /control/arm` | `{kind, generation, target_pid?}`; PID обязателен для gamepad и сверяется с выбранным окном. Ответ `{owner_id, generation}` |
| `POST /control/check` | `{owner_id, generation, duration_ms?}` для backend; без duration только проверка, с duration20–250мс — активация/продление |
| `POST /control/release` | `{owner_id}`; для gamepad это подтверждение, что нейтраль уже отправлена; чужое разрешение отклоняется |
| `POST /action`, `/step`, `/hold` | Прежние поля плюс `owner_id`, `generation`; прежняя проверка `observation_expires_ms` у hold сохранена |
| `POST /stop` | Общий отзыв, без ожидания actionGate |

Состояния: `disarmed → reserved/active → revoking → disarmed`. Gamepad-reservation на создание устройства живёт до5с и сама не разрешает команды; активная аренда геймпада —20–250мс. Обычное добровольное освобождение уже нейтрального геймпада меняет разрешение, но не поколение захвата; `/stop` и прерывания меняют поколение. Это позволяет явно запускать следующие фазы ограниченной диагностики и сохраняет запрет после внешнего вмешательства.

`LiveActuator` явно получает keyboard-разрешение и освобождает именно его. Отказ в arm не вызывает глобальную остановку чужого владельца. Отложенный ответ arm после локального stop освобождается без отправки команды. Fallback к старому `/action` удалён. `GamepadWorker` передаёт Python путь к приватному connection.json; токен и разрешение backend не выводит в ready/status/отчёты. Старый мост без нового протокола отклоняется до создания реального устройства.

## Ограничения

Нет нового измерения времени реакции/нейтрали в GTA. Watchdog Python имеет интервал20мс, запрос разрешения — сетевой timeout100мс; это настройки, а не доказанная задержка остановки. Нейтраль подтверждается успешными вызовами reset/update, а не новым живым измерением XInput; она не гарантирует остановку машины. Если backend исчез без ACK, старый мост остаётся `revoking`: автоматического захвата новым владельцем в нём нет. Перезапуск моста не снимает файловую блокировку живого backend.

Старые raw-клавиатурные CLI и `CautiousDriver`, не передающие разрешение, теперь получают отказ; их прежние примеры не являются готовым live-входом. Полный `drive-safety-gate`, доказанная калибровка и обязательный срок исходного наблюдения до всех Python/диагностических путей остаются отдельными незавершёнными задачами. `trial --drive` по-прежнему запрещён. Этот этап закрывает общий владелец/явный re-arm, но не весь аудит и не допуск к автономному вождению.
