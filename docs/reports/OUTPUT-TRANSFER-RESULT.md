# Передача выходных буферов ONNX worker — 6 ноября 2026

**Найдено умеренное ускорение без изменения выходов моделей.** Передача CPU-буферов вместо их копирования между worker и основным потоком уменьшила медиану полного анализа с 77–78 до 73 мс. Добавлена опция `transferOutputs: true`, по умолчанию выключена. Это не устранение 70 мс Running и не замер под нагрузкой GTA.

## Протокол и область изменения

Офлайн A/B/B/A: A — structured clone выходов, B — те же выходы через `postMessage` с уникальными ArrayBuffer в transfer list. По две сессии/worker с общим последовательным допуском DirectML, YOLOP640 + SegFormer512, intra-op3, sequential, memPattern=false. Сначала использованы изолированные диагностические копии worker с одинаковым кодом учёта в A/B. Порогов, графов, пиксельных операций и размеров не меняли. Два прогрева перед каждой серией.

Те же 54 старых development/historical кадра, что в [абляции](./PERCEPTION-ABLATION-RESULT.md); основные 40 равномерных кадров анализируются отдельно. Всего216 измерений, 54 уникальных кадра. Защищённая поездка и пустынная validation не использованы. Кадры предзагружены; время до окончания геометрии, без диска, хеширования, оценки совпадений и прогрева. Нет OCR, захвата, ввода. GTA отсутствовала при проверках до/после; прочая нагрузка не контролировалась.

Протокол записан до запуска: все сырые и итоговые выходы должны совпасть; буферы B должны действительно отсоединиться у отправителя; сохранённый результат SegFormer должен пережить следующий run без изменения. Для временного фильтра оба p95 B должны быть ниже обоих A, а медианы RPC-minus-native — ниже обоих A для каждой модели. Успех этого офлайн-фильтра не включает опцию в живой профиль автоматически.

Временной фильтр пройден. Медиана улучшилась примерно на4,5–5,7мс; A1 имеет заметно больший хвост, поэтому нельзя приписывать весь его разрыв B исключительно передаче буферов. Устойчивого снижения общего CPU нет: B2 немного выше A2. Не заявляется экономия70мс CPU.

Медианы native YOLOP:25,25/24,87/24,91/24,87; SegFormer:20,14/20,22/20,09/20,15. Существенного ускорения самого native run здесь нет. `RPC−native` включает передачу входов, доставку выходов и планирование потоков; это не чистый замер копирования памяти и не время GPU.

YOLOP возвращает7158400байт, SegFormer1245184байта: вместе около8,4МБ на наблюдение. В двух B, включая прогрев, отсоединены **448/448 выходных буферов**; в A —0. Таким образом, на этих моделях и установленной версии Node передача действительно состоялась. Входные данные по-прежнему клонируются и принадлежат вызывающему потоку. Передачи RAM↔VRAM этим не устранены.

## Совпадения и внедрение

- 160 сравнений с40 сохранёнными эталонами точные во всех четырёх сериях: маски, классы, боксы.
- 162 сравнения повторов точные: дополнительно SHA-256 всех сырых выходных тензоров обеих моделей, semantic probabilities и геометрии. Проверки пересекаются и относятся к повторённым кадрам.
- Сохранённый выход SegFormer не изменился после следующего native run.
- После переноса опции в общий API ещё54/54 результата рабочего worker через `createInferenceSession(...,{transferOutputs:true})` совпали с диагностическим A1, включая сырые тензоры. Это отдельная проверка реализации, без нового заявления об ускорении.
- **134 JS +16 Python** прошли. Новый тест на настоящем CPU ONNX проверяет равенство результатов, сохранность входов и старых выходов после следующего run и release; некорректный тип опции отклоняется.

Опция задаётся третьим аргументом `createInferenceSession(model, ortOptions, {mode:'worker', transferOutputs:true})` либо `WorkerInferenceSession.create`. Обычные `Perception.load`/`SemanticRoad.load` остаются на прежнем default=false. Планировщик, таймауты, освобождение сессий, контроль возраста, F8 и leases не менялись. C# не менялся. Опция относится к результатам worker, а не к настройкам ONNX Runtime или GPU I/O Binding.

По [документации Node20](https://nodejs.org/docs/latest-v20.x/api/worker_threads.html#considerations-when-transferring-typedarrays-and-buffers), transfer list передаёт владение ArrayBuffer и лишает отправителя доступа к его содержимому; не каждый Buffer допускает передачу. Поэтому проверены именно реальные выходы установленных моделей, без переноса вывода на произвольные native-модули/буферы.

Данные: `D:/GTA-AI-data/experiments/result-transfer-20261106/` — protocol, timings, summary, verification-protocol/verification, worker-статистика и SHA-256-манифест; скрипты и логи — `work/result-transfer/`. Исходные отчёты и веса сохранены. Диагностические серии закончены до изменения общего API; прежние хеши зафиксированы, а новые — отдельно в verification-protocol.

Перед включением в рабочий профиль нужен пассивный замер с OCR и полным возрастом наблюдения при контролируемой нагрузке игры. Причина70мс Running остаётся не доказанной: [intra-op1 уже проверен](./THREAD-OPTIONS-RESULT.md), а редкий SegFormer требует иной проверки качества/согласования кадров.
