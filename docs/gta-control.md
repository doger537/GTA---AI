# GTA Control

> Исходники перенесены в монорепозиторий. Канонические пути и команды из корня: [архитектура](ARCHITECTURE.md) и [главный README](../README.md). Команды с короткими прежними именами ниже относятся к историческому запуску из `outputs/GtaAutopilot` или `outputs/GtaControl`; эти каталоги содержат переходники.

Общий владелец keyboard/gamepad реализован: перед клавиатурными командами обязателен `/control/arm`, затем `owner_id` и `generation`. Python отдельно проверяет разрешение и удерживает общий процессный guard до нейтрали. `/stop`, F8, потеря фокуса и истечение срока отзывают разрешение; продолжение требует явного arm. [Протокол и проверки](reports/INPUT-OWNERSHIP-RESULT.md).

`/hold` использует общий gate с `/action` и `/step`, а `/stop` остаётся независимым. `observation_expires_ms` задаёт абсолютный deadline в исходной capture-clock сервера; сервер ограничивает им lease и отвергает истёкшее значение. Старые raw-запросы без разрешения владельца больше не выполняются. Для реальных Python-команд `source` и фиксированный capture-clock deadline теперь обязательны; [контракт](reports/DECISION-DEADLINE-RESULT.md). Полный допуск к езде пока не завершён. [Остальные пункты аудита](reports/AUDIT-REMEDIATION.md).

В исходниках доступен экспериментальный флаг `--parallel-encoding`: перед кодированием HUD и миникарта клонируются, три независимых Bitmap обрабатываются параллельно. Обычный запуск последовательный. Кандидат прошёл сборку/self-test и офлайн-проверку, но ещё не установлен и не проверен с полным живым OCR/ONNX. Заголовок `X-Obs-Encoding-Parallel`/поле клиента `encoding_parallel` показывают режим; дочерние таймеры при параллельном режиме перекрываются. [Отчёт](./reports/PARALLEL-ENCODING-RESULT.md).

`GET /observation` дополнительно возвращает `X-Obs-*-Ms`: capture-work/acquire/encode/road/hud/map/road-resize/road-codec/pack/prepare. Это вложенные интервалы Stopwatch, не независимые расходы. Тело/version1 и исходные timestamps сохранены. JS-клиент отдаёт `server_timing` (null у старого моста) и `transport_timing`: headers/body/concat/request. Ожидание заголовков включает подготовку кадра сервером; его нельзя считать чистым HTTP. [Измерения и границы](./reports/ACQUISITION-PROFILE-RESULT.md).

`GET /hud` возвращает небольшой участок спидометра в PNG без уменьшения, с прежней авторизацией и проверкой фокуса. Заголовки `X-Hud-*` описывают границы и размер исходного клиента; `X-Capture-*`, `X-Frame-Age-Ms` и номер задают время наблюдения. [Проверка нового канала](./reports/NATIVE-HUD-RESULT.md).

Добавлен канал направления `GET/POST /navigation` с прежней авторизацией. POST принимает `{ "intent": "left", "source": "user", "ttl_ms": 5000 }`: intent — `lane_follow/straight/left/right/stop`, source — `user/planner/gps`, TTL — 100–10000 мс. Он сохраняет намерение и не нажимает игровые клавиши. Истечение срока и остановка сбрасывают намерение. Кадры передают `X-Nav-*` с интервалом действия; рекордер сохраняет его для последующей подготовки данных. GPS-планировщик в мост не включён. [Проверки и ограничения](./reports/GUIDANCE-RESULT.md).

Локальный мост управления GTA V для Windows. Готовый файл — **GtaControl.exe**.

## Осторожные манёвры — эксперимент

**Исторический интерфейс ниже не адаптирован к новому владению вводом.** Текущая сборка отвергает его команды без `owner_id/generation`. Этот пример не является разрешённым live-контуром.

`cautious-driver.mjs` добавляет короткие команды с локальным торможением перед возвратом кадра агенту. Прямой газ ограничен 300 мс, газ с рулением — 150 мс; после импульса удерживается ручной тормоз 700 мс. Подготовка `arm()` сначала удерживает тормоз 1500 мс. Вызывать только сидя за рулём. Проверка фактической скорости и посадки водителем программно отсутствует.

```js
import { connect } from '../packages/protocols/bridge-client.mjs';
import { CautiousDriver } from '../packages/actuation/cautious-driver.mjs';
const client = await connect();
const driver = new CautiousDriver(client);
await driver.arm();
const frame = await driver.tick({ steer: 'straight', pulse_ms: 300 });
// Агент анализирует frame перед следующим манёвром.
await driver.stop();
client.close();
```

Проверено четыре пробы: прямые импульсы 200 и 300 мс, левый и правый — по 150 мс. Полный манёвр с торможением и кадром занял 1107–1245 мс, среднее 1162 мс. Видимых столкновений в этих пробах не было. Небольшое прямое перемещение наблюдалось; заметное изменение курса при коротких поворотах не подтверждено. Режим слишком медленный для поездки; улучшение прохождения маршрута не доказано. Полный журнал — `cautious-test-results.json`.

Камера корректировалась вручную; автоматической фиксации камеры, распознавания препятствий и регулировки по реальной скорости нет. Импульс тормоза не гарантирует неподвижность на уклоне после его отпускания. Это эксперимент для малых манёвров, а не автопилот.

## Непрерывный захват и постоянное соединение

При активном окне GTA приложение непрерывно обновляет JPEG-кадр с целевой частотой 15 кадров/с. Реальная частота зависит от компьютера; в проверке получено около 13 кадров/с. Буфер содержит только последний кадр: очередь старых изображений не накапливается. При потере фокуса захват приостанавливается и буфер очищается.

`GET /frame` возвращает готовый кадр. Если подходящего кадра пока нет, ожидание ограничено 700 мс; принимаются кадры, захват которых начался не более 250 мс назад. `/step` ждёт кадр, захват которого начался как минимум через 60 мс после завершения команды, чтобы исключить изображение до действия. Для длительных анимаций одного такого кадра может быть недостаточно.

`GET /capture-status` возвращает целевую и измеренную частоту, возраст и номер кадра. Эти данные также отображаются в окне приложения. Ответы с изображением содержат `X-Frame-Sequence` и `X-Frame-Age-Ms`.

Для постоянной сессии используйте **bridge-client.mjs**. Модуль можно импортировать один раз в долгоживущий Node.js-процесс и вызывать между решениями агента:

```js
import { connect } from '../packages/protocols/bridge-client.mjs';
const gta = await connect();
const frame = await gta.frame(); // { bytes, mimeType, sequence, frame_age_ms, roundtrip_ms, ... }
const next = await gta.step({ keys: ['w'], duration_ms: 300 });
await gta.stop();
// При завершении сессии:
gta.close();
```

Клиент повторно использует TCP-соединение, без перезапуска процесса для каждой команды. У «Стоп» отдельное соединение, поэтому он не ждёт завершения действия. Сервер закрывает бездействующие соединения примерно через 15 секунд, после чего клиент открывает новое при следующем запросе. При ошибках действия автоматически не повторяются: потеря ответа не означает, что ввод не выполнился.

В живой проверке пять последовательных запросов `/frame` использовали одно соединение; получение кадра занимало 1–18 мс, возраст кадра — 62–109 мс. Проверка команды без нажатий на 100 мс вместе с ожиданием кадра заняла около 306 мс со стороны постоянного клиента. В другой проверке запрос остановки занял 2 мс и прервал команду на 1500 мс примерно через 116 мс. Это отдельные замеры, без времени размышлений и вызовов инструментов агента.

Непрерывный захват не добавляет автономное принятие решений или анализ видеопотока моделью. Агент всё ещё выбирает действия по отдельным полученным кадрам.

## Быстрый режим

`POST /step` принимает то же JSON-тело, что `/action`, и возвращает JPEG-кадр после завершения действия. Захват этого кадра должен начаться минимум через 60 мс после отпускания клавиш, чтобы игра успела отрисовать изменение. Длинные анимации и переходы меню могут потребовать дополнительного ожидания.

Кадр сохраняет пропорции, вписывается в 1280×720, качество JPEG — 75. Маленькие изображения не увеличиваются. Старый `/screenshot` сохраняет полноразмерный PNG для мелких надписей.

В заголовках ответа `/step` доступны `X-Action-Ms`, `X-Capture-Ms` (ожидание готового кадра после действия), `X-Total-Ms` и `X-Action-Interrupted`. Время сервера не включает запуск клиента, вызовы инструментов и анализ изображения агентом. При потере фокуса после действия кадр не снимается: ответ 409; само действие к этому моменту могло уже выполниться, поэтому повторять его вслепую нельзя.

```text
node client.mjs step action.json frame.jpg
```

Один вызов возвращает и результат действия, и файл кадра. `GET /frame` получает компактный JPEG без игрового ввода. `/stop` остаётся доступен во время действия. Новый `/step` блокирует другие игровые команды до получения кадра.

В предыдущей версии без непрерывного захвата проверено в GTA: действие W на 400 мс и кадр выполнены за 563 мс внутри приложения, из них 61 мс заняли захват и кодирование. В этой пробе JPEG занимал 93 738 байт; соседний полноразмерный PNG — 3 767 352 байта. Это сравнение размера двух соседних кадров, а не гарантия одинаковой скорости в каждой сцене.

## Запуск

1. Открой `GtaControl.exe` или `Start.cmd`.
2. Запусти GTA V. В приложении нажми «Обновить», если игра ещё не появилась.
3. Выбери окно игры и переключись обратно в GTA.
4. Напиши в чате «приложение запущено, проверяй». Агент сможет прочитать локальный `connection.json` и обратиться к API.

Приложение работает в обычном режиме пользователя. Совместимость ввода с GTA на этом компьютере нужно проверить в игре: успешная сборка и тесты API ещё не означают, что игра примет команды.

## Управление

- Клавиши передаются через Windows SendInput с аппаратными скан-кодами.
- Одна команда может удерживать до восьми клавиш и три кнопки мыши одновременно.
- Длительность: от 20 до 5000 мс; по завершении клавиши отпускаются.
- `dx` и `dy` задают относительное движение мыши в начале команды.
- **F8**, кнопка «СТОП», запрос `/stop` или потеря фокуса GTA прекращают ввод. Проверка остановки выполняется примерно каждые 10–40 мс, без гарантии жёсткого реального времени.
- Для следующей команды требуется снова активировать окно GTA.
- Одновременно выполняется одна команда. Запрос остановки обрабатывается отдельно.
- Снимок содержит клиентскую область видимого окна игры. Перекрывающие окна и оверлеи могут попасть в кадр.

## API

Адрес с автоматически выбранным портом и случайный токен сохраняются в `connection.json` рядом с приложением при каждом запуске. Файл удаляется при обычном закрытии. Его содержимое не нужно отправлять другим людям.

Сервер слушает только `127.0.0.1`. Все запросы требуют заголовок `Authorization: Bearer <token>`. Запросы с заголовком браузерного Origin отклоняются.

| Запрос | Результат |
| --- | --- |
| `GET /status` | Наличие окна, фокус, состояние, поддерживаемые клавиши |
| `GET /capture-status` | Частота, возраст и номер кадра непрерывного захвата |
| `GET /screenshot` | PNG клиентской области GTA; требуется фокус игры |
| `GET /frame` | Последний готовый JPEG клиентской области GTA |
| `POST /action` | Выполнение JSON-команды; ответ приходит после отпускания клавиш |
| `POST /step` | Выполнение команды и JPEG-кадр одним ответом |
| `POST /stop` | Немедленная отмена текущей команды и отпускание клавиш |

Пример тела `/action` — удерживать W и Shift одну секунду:

```json
{"keys":["w","shift"],"duration_ms":1000}
```

Пример одновременного движения и поворота:

```json
{"keys":["w","a"],"duration_ms":350,"dx":10,"dy":0}
```

Поддерживаются буквы, цифры, `shift`, `ctrl`, `alt`, `space`, `tab`, `escape`, `enter`, `backspace`, стрелки и `num0`–`num9`. Полный список возвращает `/status`. Кнопки мыши: `left`, `right`, `middle`.

При потере фокуса API возвращает 409. При неверной команде — 400, при неверном токене — 401. Успешное принятие SendInput системой не подтверждает реакцию игры: её проверяют по следующему кадру.

## Клиент для Node.js

В папке приложения:

```text
node client.mjs status
node client.mjs screenshot frame.png
node client.mjs action action.json
node client.mjs step action.json frame.jpg
node client.mjs stop
```

Для игровых команд GTA должна быть активна в момент запроса. Клиент удобно запускать из фонового процесса, чтобы терминал не забрал фокус игры.

## Исходный код и проверка

`GtaControl.cs` — полный исходный код приложения, использует .NET Framework и системные библиотеки Windows. `Build.ps1` — сборка через Windows PowerShell, если выполнение локальных скриптов разрешено политикой системы. `Start.cmd` также умеет собрать отсутствующий EXE прямым вызовом компилятора без изменения политики выполнения.

Встроенная проверка не отправляет клавиши и не снимает экран:

```text
GtaControl.exe --self-test C:\полный\путь\test-results.json
```

Она проверяет разбор команд, ограничения длительности, раскладку структуры Windows INPUT, авторизацию HTTP, блокировку браузерного Origin и отказ снимка без выбранной игры.

## Удержание клавиш между обновлениями

`POST /hold` принимает те же `keys` и `duration_ms` (20..650 мс), а также обязательное целое `generation` из `/status`. Мышь в этом режиме не поддерживается. Ответ приходит сразу; неизменённые клавиши остаются нажатыми. Для изменения набора отпускаются только удалённые клавиши и нажимаются добавленные.

Независимый таймер проверяет срок удержания, фокус и F8 каждые 20 мс. Истечение срока, потеря фокуса и `/stop` отзывают generation. Запросы со старым generation получают 409; повторять их автоматически нельзя. На перегруженной Windows интервал таймера может увеличиваться. Завершение процесса/сбой ОС не покрываются этой гарантией.

Этот API подключён к экспериментальному `../apps/gta-control/cli/trial.mjs`. Он устраняет обязательное отпускание газа между соседними запросами; плавность полноценной езды ещё не подтверждена.
