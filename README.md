## Архитектура

```text
GTA на экране
  → GtaControl (C#, Windows): один захват → JPEG дороги + PNG HUD/миникарты
  → локальный HTTP на 127.0.0.1, бинарные изображения и метаданные
  → GtaAutopilot (Node.js): подготовка входов
      ├─ YOLOP ONNX: дополнительные машины и линии
      ├─ SegFormer ONNX: дорога, тротуар, семантические препятствия
      └─ Tesseract workers: скорость и передача
  → связный путь в изображении + проверки свежести/навигации
  → для отдельно включённых опытов: ограниченный исполнитель
      ├─ C# SendInput для существующих клавиатурных проб
      └─ постоянный Python/vgamepad backend для аналоговых команд
```

Входы нейросетей — float32. Базовые размеры: YOLOP640 и SegFormer512; последняя возвращает logits19×128×128. DirectML выбран явно. `Promise.all` перекрывает подготовку/OCR, но общий допуск сериализует два GPU-run. Отправка кадров не использует Base64. Python не перезапускается на каждой команде и не участвует в измерениях vision-only.

Геометрия ищет связный путь на сетке128×128 выше исключённой области своего кузова. Это ещё не измеренный зазор для автомобиля, принадлежность полосы или подтверждённый курс машины.

### Что выяснили о задержках

- В редких медленных кадрах83–91%времени находились внутри native ORT run, который включает вычисления, передачи и ожидания. [Трасса](docs/reports/TAIL-TRACE-RESULT.md).
- У YOLOP в записанном ORT-профиле CPU-узлов нет. У SegFormer они обслуживают небольшие int64-векторы размеров; MatMul/LayerNormalization/Resize находятся на DML. [Профиль узлов и стадий](docs/reports/ORT-NODE-PROFILE-RESULT.md).
- В ETW обнаружено ожидание ORT через `WaitForSingleObject`. Это не доказательство бесполезного spinning или очереди WDDM: ожидание может перекрывать полезную GPU-работу. [Разбор стеков](docs/reports/ETW-WAIT-STACKS-RESULT.md).
- GPU-события в новом boundedETL не получены, а CPU-кольцо сохранило только конец истории. Точное разделение GPU/copy/queue **ещё не выполнено**. [Ограничения ETW](docs/reports/ETW-BOUNDED-RESULT.md).

## Подготовка из чистого клона

Проверенная среда: Windows, Node.js20.18.1, ONNX Runtime Node1.23.2, Python3.12 для Python-компонентов; GPU GTX1660SUPER6ГБ. Для C# используется Windows PowerShell5.1.

```powershell
git clone https://github.com/doger537/GTA---AI.git
cd GTA---AI
npm ci
npm run test:core
```

`test:core` проверяет базовую логику и включённые fixtures без игры. Полный набор требует локальных моделей/записей и соответствующего окружения:

```powershell
npm test
npm run test:python
```

После доработки чтения11: **253 JS и43 Python прошли**; последняя неизменённая C#-сборка ранее прошла18 групп self-test. Хеши активов: `npm run models:verify`. Команды тестов не являются запуском автопилота.

| Команда из корня | Что проверяет |
|---|---|
| `npm run test:core` | 203 теста базовой логики и включённых fixtures; без моделей, записей и игры |
| `npm test` | 253 теста, включая локальные ONNX/OCR-активы и Python mock-процесс |

| `npm run models:verify` | Размеры и SHA-256 установленных активов по `models-manifest.json` |

[GitHub Actions](.github/workflows/ci.yml) запускает core на Linux/Windows, сборку/self-test C# и stdlib-проверки Python на Windows. Полный vision-набор требует локальных активов и не входит в облачный CI. Отдельный [аудит зависимостей](.github/workflows/security.yml) сохраняет прежний строгий порог; после обновления8 ноября локальный `npm audit` возвращает0 уязвимостей. Статус конкретного коммита — в [Actions](https://github.com/doger537/GTA---AI/actions).

Реальное OCR шести PNG проверяет полный `npm test` с локальными активами; coreCI проверяет структуру/отказы без OCR-модели. CI устанавливает зависимости через `npm ci` и проверяет core на Linux и Windows без локальных моделей, записей и памяти проекта.

### Модели и локальные данные

Большие активы в Git не входят. Для основного зрения нужны в `packages/perception/models/`: `yolop-640.onnx`, `segformer-cityscapes.onnx`, `ocr/eng.traineddata`. Активные конфигурации `segformer-config.json` и `gear-templates.json` находятся в `configs/`. Для отдельных сравнений нужен `yolop-320.onnx`. Небольшие конфигурации-образцы лежат в `configs/`, модель цифр — `configs/hud-digit-prototypes.json`; она выключена в обычном HUD-профиле.

Источники базовых весов: [YOLOP](https://github.com/hustvl/YOLOP), [SegFormer B0 Cityscapes](https://huggingface.co/Xenova/segformer-b0-finetuned-cityscapes-512-1024). Проверяйте соответствие экспортов, выходов и лицензий; случайный ONNX с похожим именем не гарантирует совместимости. Источники дополнительных моделей — [обзор](docs/reports/EXTERNAL-MODELS-REVIEW.md), сторонние notices — `docs/third-party/`.

Python-окружение создаётся отдельно в `training/training-env`; зависимости разделены по `training/requirements-*.txt`. Драйвер/реальный геймпад не нужны для офлайн-проверки. [Установка аналогового backend](docs/reports/GAMEPAD-INSTALLATION.md).

### Мост и пассивная запись

Из корня репозитория:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File apps/gta-control/Build.ps1
```

После сборки выполнить `apps/gta-control/GtaControl.exe --self-test REPORT_PATH`; затем для работы с игрой — `apps/gta-control/Start.cmd`. Свежий локальный `apps/gta-control/connection.json` создаётся мостом, содержит приватный токен и исключён из Git. Это loopback-сервис, не открытый сетевой сервер. Подробности API — [GtaControl](docs/gta-control.md).

Для пассивных записей использовать `apps/gta-control/launchers/Record-Motion-Development.cmd` и отдельно `apps/gta-control/launchers/Record-Motion-Validation.cmd`. Водит человек; роли поездок сохраняются. Переход к испытаниям управления требует проверки текущего кадра, состояния машины, ракурса и зависимости этапов плана.

## Ограничения управления

`trial` по умолчанию работает в shadow. `--drive` требует проверенный комплект калибровки, совпадающий с машиной, камерой, окном, моделями и типом исполнителя, а затем подтверждённые текущие идентичность/курс/метрическую геометрию. Комплект не установлен, runtime-измерители этих величин ещё не подключены: допуск остаётся закрыт. LiveActuator/AnalogActuator требуют `update(command, source, authorization)` с непросроченным разрешением общего gate. Перед созданием реального Python-устройства нужен отдельный startup permit. [Контракт и проверки](docs/reports/SAFETY-CHECKLIST-RESULT.md).

`calibrate-analog` и диагностические CLI также используют общий gate и три свежих наблюдения перед arm. Требуются явные `--pid=PID --vehicle-profile=NAME --camera=rear|hood`. Диагностика допускает только ограниченный руль с нулевыми педалями; старые диагностические `--pedals/--movement/--calibration` отклоняются. `/action`, `/step`, CautiousDriver и standalone neutral-test выведены из использования. Исторические примеры не включают управление через обход нового допуска.

F8, фокус окна, generation и watchdog сохраняются. Срок аналоговой команды не более250 мс, предел возраста наблюдения450 мс. Нейтраль снимает ввод, но не гарантирует остановку автомобиля. Старая маска не становится свежей при получении нового кадра от другой модели. Экспериментальные `--drive`/калибровочные режимы не являются готовым повседневным автопилотом.

## Дальнейшая работа

1. Собрать реальные независимые калибровочные сессии и подключить измерители идентичности/курса/метрической геометрии к реализованному gate. Программный чек-лист проверен офлайн; фактический допуск к автономной езде ещё не получен.
2. По завершённой абляции320 не заменяет640: есть регрессии на машинах. Исследовать ускорение с сохранением выходов или отдельный детектор; проверить полный возраст наблюдения в движении. Для анализа ожиданий сначала проверить сбор GPU-событий и достаточность CPU-истории.
3. Закрыть пробел малых скоростей и направления камеры, провести измеряемую аналоговую калибровку.
4. Только после проверенного удержания пути/остановки — препятствия, GPS-повороты и короткий маршрут.

Подробнее: [модули и инструменты](docs/autopilot.md), [текущее состояние](CURRENT-STATUS.md), [план](DEVELOPMENT-PLAN.md).

## Что опубликовано

В репозитории: исходники, конфигурации, небольшие fixtures, тесты и Markdown-отчёты. Не публикуются токены, зависимости, окружения, веса, поездки, ETL, бинарные сборки и локальная память чатов. Отчёты могут ссылаться на локальные `D:/GTA-AI-data/...` и `work/...`: эти ссылки описывают происхождение результатов, но не означают, что активы доступны в чистом клоне. Некоторые исследовательские CLI требуют адаптации локальных путей и отдельно подготовленной разметки; автоматического восстановления всех экспериментов нет.
