# Обучение на полной поездке с событиями клавиатуры

Второй эксперимент использует 832 примера поездки 2026-11-01T17-32-01-342Z для обучения новой модели с нуля. Все 880 примеров старой поездки 2026-11-01T16-49-20-088Z используются только для проверки этих весов. Исходные данные и прежняя модель сохраняются.

Архитектура та же: четыре кадра 80×45, небольшая CNN, шесть независимых кнопок. Веса редких положительных меток вычисляются только по обучающей поездке как число отрицательных / число положительных, в пределах 1–40. Прежде предел был 6. Изменились и данные, и веса ошибки; разницу нельзя приписывать только одному изменению.

Новое разделение проверяет разные записи, а не соседние кадры. При этом старая поездка уже изучалась при разработке предыдущей модели. Это проверка разработки; окончательный тест потребует третью поездку, которую не используют для обучения или подбора настроек.

Воспроизведение из папки GtaAutopilot:

```text
node train-bc.mjs datasets/2026-11-01T17-32-01-342Z --validation-dataset=datasets/2026-11-01T16-49-20-088Z --epochs=2
```

Либо Train-New-Recording.cmd. Запуск создаёт новую папку trained/<время>/ и не перезаписывает прошлый эксперимент. config.json сохраняет обе исходные поездки; report.json содержит результаты по кнопкам и базовый прогноз, веса классов, скорость и проверку повторной загрузки.

Ключ --validation-dataset требует отличающийся идентификатор поездки и совместимую схему. Одноимённые файлы из разных поездок читаются из отдельных каталогов и отдельных кэшей. Передача той же записи как обучающей и проверочной запрещена. 36 тестов прошли, включая эти проверки и сохранение модели.

evaluate-bc.mjs использует сохранённую в config.json проверочную поездку по умолчанию. Явная оценка на самой обучающей поездке помечается как training-set evaluation, а не holdout. Ни один из этих инструментов не отправляет команды в GTA.

## Результат выполненного запуска

Модель сохранена в `trained/2026-11-02T06-40-36-509Z/`. Две эпохи завершились штатно примерно за 198 секунд. Повторная загрузка дала нулевую разницу прогнозов. Средний прогноз модели около 3 мс, без захвата и подготовки изображений.

При пороге 0,5 точное совпадение набора кнопок на 880 примерах старой поездки составило 3,98%: модель выбирала A на 861 кадре, из которых только 57 содержали A в записи. Усиление редких классов привело к избыточным срабатываниям; такой результат нельзя считать готовым управлением.

Добавлен calibrate-bc.mjs: порог каждой кнопки выбирается по максимальному F1 только на 832 обучающих примерах. Проверочные метки читаются после завершения выбора. Порог Shift выше 1 отключает действие, которого не было в обучающих данных. Результаты и пороги сохранены в calibration.json, исходный report.json не изменён.

| Проверка на старой поездке | Точное совпадение кнопок | Средний F1 поддержанных кнопок |
|---|---:|---:|
| Исходный порог 0,5 | 3,98% | 0,238 |
| Пороги по обучающим примерам | 46,48% | 0,191 |
| Всегда W | 50,57% | 0,157 |

Настройка уменьшила лишние команды, но снизила средний F1 относительно исходного порога. После настройки распознаны только 2 из 57 левых поворотов, 13 из 148 правых и ни одно из 18 нажатий S. Остались три прогноза с конфликтующими кнопками. Качество недостаточно; управление GTA не включено. 58,29% совпадений на обучающей поездке не являются оценкой переноса на новую дорогу.

Это другой набор проверки, чем 213 примеров в первом отчёте: сравнивать 46,48% с прежними 27,23% как доказательство улучшения нельзя. Сменились автомобиль, ситуации, качество меток и настройки обучения. Конкретный вклад каждого фактора по этому эксперименту не установлен.

Для повторной проверки после обучения:

```text
node calibrate-bc.mjs trained/2026-11-02T06-40-36-509Z
node predict-bc.mjs trained/2026-11-02T06-40-36-509Z datasets/2026-11-01T16-49-20-088Z --index=700 --calibrated
```

Следующая инженерная задача — раздельные согласованные выходы руля и педалей, проверка влияния ракурса/своего кузова и использование наблюдаемого состояния движения. Для проверки переноса нужна отдельная запись с тем же автомобилем и задним ракурсом. Для выбора поворота по маршруту потребуется также навигационная команда: текущая сеть цели поездки не получает. Простое увеличение числа эпох не решает эти неоднозначности автоматически.
